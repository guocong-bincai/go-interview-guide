# 技术面试复习方法论：知识体系、错题本与模拟面试

> 考察频率：★★★★★（决定你复习效率的元技能）  难度：★★★☆☆
> 适用：面试准备全周期，尤其适合在职、时间碎片化的工程师

---

## 核心答案（30 秒版）

高级工程师复习面试最大的敌人不是"知识不够"，而是**"范围失控 + 假性掌握"**。方法论三件套：**① 以简历和 JD 定复习范围**（简历写了什么、JD 要什么，就复习什么，没写的别碰）；**② 用"知识体系 + 错题本"替代零散刷题**（一个专题一份主线资料，答不出的进错题本，反复复盘到能脱稿）；**③ 用模拟面试验证**（每周一次，从简历开始追问，暴露"以为会其实不会"的盲区）。核心原则：**同一道题看三份答案还说不出来，就该开始脱稿讲，而不是收藏第四份资料。**

## 1. 复习的第一步：定范围，不是定题库

### 1.1 范围从两个来源收缩

```
来源一：简历里主动写了什么
  → 写了"熟悉 Redis 集群"，就必须能接住 Redis 集群的任何追问
  → 写了"负责订单模块"，就必须能讲透订单项目的取舍和细节

来源二：目标 JD 明确要求什么
  → JD 反复出现的关键词 = 高频必考
  → JD 没写、简历也没写的，别花时间
```

⚠️ **最大的时间黑洞**：一边复习一边往简历里加新技术，导致复习范围无限扩大。**简历定稿后再开始复习，复习范围跟着简历走。**

### 1.2 复习周期参考

| 阶段 | 4 周压缩版 | 8 周标准版 | 内容 |
|------|-----------|-----------|------|
| 项目与简历 | 第 1 周 | 第 1 周 | 项目底稿、简历润色、自我介绍 |
| 语言与基础 | 第 2 周 | 第 2~3 周 | Go 核心（GMP/GC/并发）、Linux |
| 数据库/中间件 | 第 2 周 | 第 3~4 周 | MySQL/Redis/Kafka 按简历选 |
| 系统设计 | 第 3 周前半 | 第 5 周 | 高频设计题 |
| 算法 | 每天穿插 | 第 6 周集中 | LeetCode 高频，每天保持手感 |
| 分布式/排查 | 第 3 周后半~第 4 周 | 第 7 周 | 按简历选 |
| 模拟 + 收口 | 最后 2 天 | 第 8 周 | 模拟面试、错题复盘 |

> 每天稳定时间不足 2 小时，选 8 周版。已开始投递或面试临近，走 4 周版，但**范围跟着简历收缩**：简历没有 Kafka，JD 也没要求，就别在 MQ 实现细节上花两三天。

## 2. 知识体系：从"点"到"树"

零散背题的问题是：**面试官换个角度问就答不出**。要把知识组织成体系。

### 2.1 以 Redis 为例的体系化

```
Redis
├── 数据结构：String/Hash/List/Set/ZSet → 各自适用场景、底层编码
├── 持久化：RDB/AOF → 触发条件、优缺点、混合持久化
├── 高可用：主从/Sentinel/Cluster → 故障转移、脑裂
├── 缓存问题：穿透/击穿/雪崩 → 各自解决方案
└── 集群：分片、槽、扩容迁移、热点 key
```

**要求**：每个节点都能**从浅讲到深**，并且知道**节点之间的联系**（比如"缓存雪崩"和"持久化"没关系，但和"高可用/降级"有关）。

### 2.2 专题资料"一份主线"

```
✅ 一个专题保留：1 份主线资料 + 少量专题文章
❌ 同一道题收藏第 4 份答案——这是"假性学习"的典型信号
```

**费曼式自测**：
> 合上资料，能不能**用自己的话**把一个机制讲清楚（甚至讲给一个不懂的人听懂）？能讲清才是真掌握。

## 3. 错题本：把"不会"变成"会"

### 3.1 错题本模板

```markdown
| 日期 | 题目 | 我当时的回答 | 正确答案要点 | 我的盲区 | 掌握程度 |
|------|------|-------------|-------------|---------|---------|
| 8/15 | goroutine 泄漏排查 | 说了思路没写代码 | pprof goroutine / 未关闭 channel | 并发调试 | ⭐⭐ |
| 8/16 | 秒杀系统设计 | 缓存穿透没答好 | 布隆过滤器 + 空值缓存 | 缓存设计 | ⭐⭐⭐ |
```

### 3.2 三种错题的处理方式

| 类型 | 处理 |
|------|------|
| **知识盲区**（完全不会） | 当天查资料搞懂，写入错题本，隔 2 天、7 天复盘 |
| **表达问题**（会但答得乱） | 重新组织语言，形成"标准答案"，对着镜子/录音练 |
| **面试官感兴趣但我没深入** | 深入挖掘，为下一轮同公司/同方向准备 |

**复盘节奏**：错题本**每次面试前只看自己的错题**，不重新刷完整题库。

## 4. 模拟面试：暴露"以为会其实不会"

### 4.1 为什么要模拟

- 自己看书 → 感觉"都会了"
- 被人追问 → 才发现"讲不出来"
- **模拟的价值**：在低风险环境暴露真实水平

### 4.2 怎么做（没有同伴也能做）

```
方法一：找同伴互相 mock（最优）
  → 让对方从简历开始问，项目追问后再进入八股/场景题
  → 互相记录对方"卡壳点"

方法二：录音/录像回放（次优）
  → 自己讲一遍项目/八股，录下来回放
  → 挑语病、逻辑断点、没说清的点

方法三：AI 模拟追问（辅助）
  → 用 AI 追问，但回答后要回到文章/源码核对事实
  → AI 只能帮练表达，不能代替你验证知识准确性
```

### 4.3 模拟后的三件事

```
1. 立即记录：不会的题、答得乱的题、面试官可能追问的方向
2. 针对性补强：当天或次日解决
3. 调整策略：发现薄弱模块，下一轮重点补
```

## 5. 碎片化时间的利用（在职考生）

| 时间段 | 用途 |
|--------|------|
| 通勤/排队 | 听技术播客、看八股卡片、回顾错题 |
| 午休 30 min | 一道系统设计题想思路（不用写完） |
| 晚上 1~2 h | 主攻一个专题（读源码/写 demo） |
| 周末半天 | 模拟面试 + 算法专项 |
| 睡前 15 min | 错题本过一遍 |

**在职备考的关键**：**每天固定一个不可动摇的"复习时间块"**，哪怕只有 60 分钟，也比"有空才学"强。

## 6. 面试前 1~2 天做什么

```
❌ 不要开新专题（越开越慌）
✅ 按简历和错题收口：

□ 自我介绍：讲一遍 30~60 秒版本，确认经历/技术栈/方向一致
□ 项目：每个重点项目讲 30 秒版和 3 分钟版，卡壳处立刻补材料
□ 简历技术栈：抽查写了"熟悉/掌握"的，确认能答原理/限制/项目用法
□ 高频错题：只复盘自己的错题和薄弱点
□ 设备：线上提前检查网络、摄像头、麦克风、共享屏幕、编程环境
□ 岗位信息：再看一次 JD，准备最相关的项目
□ 心态：接受"总有不会的题"，把注意力放在"展示思考过程"
```

## 高频追问

### Q: 时间不够，只能复习 2 周怎么办？
> 极限收缩范围：**只复习简历上写的 + JD 要求的 + 目标公司高频真题**。优先保：① 项目底稿（必考）；② Go 核心（GMP/GC/并发，Go 岗必考）；③ 目标公司高频系统设计题。放弃"全面覆盖"的执念。

### Q: 八股文到底要不要背？
> 不要"死背"，要"理解 + 能讲"。面试官一追问"为什么"就能识破背稿。正确做法：**理解机制 → 用自己的话讲 → 准备 2~3 层追问**。八股是"入场券"，但要答出深度才有区分度。

### Q: 刷题刷多少道才够？
> 数量不如质量。**LeetCode 高频 100~150 道（覆盖各类题型模板）** 远好过随机刷 500 道。重点：从"做出来"到"能讲清思路 + 复杂度 + 边界"。字节等公司偏系统设计类算法题，提前针对性准备。

### Q: 复习了但面试还是紧张、发挥不出来怎么办？
> 紧张源于"不确定"。两个办法：① **多模拟**——mock 3 次以上，临场会明显放松；② **准备"安全牌"**——准备 2 个能流畅讲 15 分钟的深度话题，心里有底就不慌。把面试当成"技术交流"，而不是"考试"。
