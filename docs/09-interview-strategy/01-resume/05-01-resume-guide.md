# 5-8 年工程师简历写法指南

> 优先级：P1  投递前必看

## 面试官考察意图

简历是面试的**第一关**，但大多数 5~8 年工程师的简历问题不是"写得太少"，而是"写得太像"——没有区分度。面试官看一份简历的平均时间是 **6~10 秒**，靠的是关键词扫描。简历的核心目标是**通过 ATS 初筛 + 引发面试官兴趣**，而不是展示工作量。

## 核心答案（30 秒版）

5~8 年工程师简历的核心是**量化 + 区分度**。项目经历要用"规模数字 + 技术挑战 + 结果"的三段式，拒绝"负责/参与/熟悉"三件套。差异化竞争力体现在：技术深度（能讲源码）、架构设计（能主持方案）、影响力（技术分享/开源）。简历关键词要和对标 JD 强匹配。

## 深度展开

### 1. 核心原则：量化一切

**反面教材**（90% 候选人的写法）：
```
负责订单系统开发，使用 Go 语言和 Redis 缓存，提升系统稳定性。
```

**正面示范**：
```
主导日均 500 万订单交易系统设计与实现，P99 延迟 < 50ms，峰值 QPS 2万+
技术挑战：库存超卖、分布式事务一致性
方案：Redis Lua 原子扣减 + RocketMQ 事务消息，最终库存准确率 99.999%
```

**五类可量化指标**：

| 指标类型 | 示例写法 | 面试官关注点 |
|---------|---------|------------|
| **QPS / 延迟** | "P99 < 50ms"，"日均请求 5000 万" | 性能敏感度 |
| **数据量** | "单表 10 亿行"，"PB 级存储" | 规模经验 |
| **成本 / 效率** | "优化后资源成本降低 40%"，"CI 从 30min→8min" | 工程效率 |
| **团队规模** | "带 5 人小组"，"跨 10 人协作" | 领导力 |
| **业务结果** | "支撑双十一峰值流量"，"订单转化率提升 15%" | 业务价值 |

**如何挖掘量化数据**：
- 查监控系统的历史峰值数据
- 问产品/运营同学要业务指标
- 对比优化前后的具体数字
- 从周报/月报中提取

### 2. 项目描述五段式

每段项目经历按以下结构写：

```
[背景 1-2句] → [挑战/痛点 1-2句] → [你做了什么 3-4句] → [结果量化 1-2句] → [沉淀/复盘 1句]
```

**反面案例**：
```
在某电商公司工作，负责订单系统开发，使用 Go 语言，主要技术栈包括
Redis、MySQL、Kafka，参与了系统重构和性能优化工作。
```
问题：全是套话，没有信息量，不知道做了什么、做成什么样。

**正面示范**：
```
背景：订单系统原为 Java 单体，日均 500 万订单，促销期间多次数据库被打爆
挑战：热 key 集中、库存扣减超卖、异步消息丢失
方案：① Redis 分片 + 本地缓存解决热 key ② Lua 脚本原子扣减解决超卖
     ③ RocketMQ 事务消息保证消息可靠投递
结果：P99 从 800ms 降至 45ms，峰值 QPS 支撑 2.3 万，大促零事故
沉淀：输出《分布式库存扣减方案》，被团队作为同类问题 SOP
```

### 3. 技能栈怎么写

**分级标准**（说"精通"就要能讲源码）：
| 级别 | 含义 | 面试官预期 |
|------|------|-----------|
| **精通** | 可以讲清楚底层原理/源码，能解决疑难问题 | 能手写实现，能回答追问 |
| **熟练** | 日常高频使用，了解最佳实践和坑 | 能独立负责该模块 |
| **了解** | 知道基本概念，用过 demo | 问基础概念能答出来 |

**不应该写的（5~8 年默认会的，不加分）**：
```
❌ 熟悉 Docker、K8s（除非你是 DevOps 方向）
❌ 了解微服务（太泛）
❌ 掌握 Git（所有工程师都会）
❌ 熟悉 Linux（默认）
```

**应该突出的技术深度点**：
```
✅ 深入 Go GMP 调度原理，熟悉 pprof 性能分析
✅ 精通 Redis 数据结构和集群模式，有 10 亿级 key 治理经验
✅ 主导过 MySQL 到 TiDB 的迁移项目
✅ 精通 gRPC HTTP/2 协议，有 Protobuf 定制化经验
✅ 了解 etcd Raft 协议实现，有分布式配置中心设计经验
```

### 4. 5~8 年工程师的差异化竞争力

**技术影响力**（拉开差距的关键）：
```
✅ 内部技术分享 20+ 场，主讲 Go 并发编程
✅ 开源贡献：向 etcd 提交 PR（已合并），向 go-redis 报告并协助修复 bug
✅ 输出技术文档：《Go 服务稳定性治理手册》，全组 50+ 人使用
✅ 主导团队编码规范制定，引入 golangci-lint，代码审查效率提升 30%
```

**跨团队协作与推动**：
```
✅ 作为核心工程师推动会员系统从单体拆分为微服务
✅ 协调 5 个团队完成双十一大促备战，零事故
✅ 主导数据库中间件选型，调研 3 种方案并落地
```

**架构设计经验**：
```
✅ 从 0 设计订单系统架构，支撑 3 年业务 10 倍增长
✅ 设计多活架构，实现 RPO=0，RTO < 30s
```

### 5. 简历 ATS 关键词优化

**高频关键词清单**（根据 JD 选择性突出）：
```
Go / Golang / 高并发 / 分布式 / 微服务
gRPC / Protobuf / HTTP/2 / RESTful
MySQL / TiDB / PostgreSQL / 索引优化 / 事务隔离级别
Redis / 集群 / 持久化 / Lua 脚本 / 热 key / 大 key
Kafka / RocketMQ / 消息队列 / 事务消息
容器 / Docker / Kubernetes / 服务网格 / Istio
链路追踪 / Prometheus / Grafana / 可观测性
网关 / 限流 / 熔断 / 降级 / 负载均衡
分布式事务 / TCC / Seata / Saga
性能调优 / pprof / 内存泄漏 / goroutine 泄漏
```

**JD 对齐技巧**：
1. 先读 JD 3 遍，划出高频词
2. 把这些词"翻译"成你的经历描述
3. 简历中按相关度排序，最匹配的放最前面
4. 如果 JD 写了"有开源贡献优先"，但你没有，可以写"日常阅读 go-redis 源码"

### 6. 简历格式建议

**结构顺序**（5~8 年）：
```
个人信息（姓名/手机/邮箱/GitHub/博客，不放照片）
个人总结（3 行，核心优势 + 技术栈 + 亮点）
工作经历（倒序，最近 2 段最详细）
项目经历（2~3 个核心项目，深度展开）
技能清单（按熟练度分层）
```

**常见问题**：
- 简历控制在 **2 页**以内（1 页最佳）
- PDF 格式，文件名 `姓名-公司-职位.pdf`
- 不要用表格式排版（ATS 不好解析）
- 避免花哨的 HR 简历模板（会被当成转行的）

## 高频追问

### Q: 项目经历写多了显得冗余，怎么办？
> 简历不是写你做了什么，而是写**你做成了什么**。每个项目控制在 4~6 行。原则：最近 2 段项目详细写，更早的略写。

### Q: 简历石沉大海没有面试，什么原因？
> 通常三个原因：① 关键词不对（ATS 扫描不过）；② 经历描述太空（没有量化）；③ 跳槽太频繁（3 年换 2 次以上）。先对标 JD 检查关键词，再找同学帮忙 mock review。

### Q: 创业公司经验怎么写才能被认可？
> 创业公司的优势是"从 0 到 1"和"独当多面"。突出：① 你负责的系统规模（用户量/数据量/QPS）；② 你做的技术决策（为什么这么选型）；③ 你的全栈能力。不要只写"负责全面工作"。
