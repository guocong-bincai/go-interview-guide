# Go 1.22 增强版 ServeMux：方法匹配、路径变量与优先级规则

> 考察频率：★★★★☆  优先级：P0（Go 1.22+ 后端高频）
> 关键词：ServeMux、PathValue、wildcard、method matching、路由优先级、405

---

## 面试官考察意图

考察候选人**对标准库 HTTP 路由能力的更新认知**。
很多人的知识停留在"标准库路由很弱，只能用 gin/chi"。
Go 1.22 之后，`net/http.ServeMux` 已经支持 **方法匹配 + 路径变量 + 通配符**，
高级候选人要能讲清楚**语法、优先级规则、以及什么时候仍然需要第三方框架**。

---

## 核心答案（30 秒版）

Go 1.22 起，`http.ServeMux` 的 pattern 语法扩展为：

```
[METHOD ][HOST]/[PATH]
```

| 语法 | 含义 | 示例 |
|------|------|------|
| `GET /users/{id}` | 路径变量，占位符必须整段匹配 | `r.PathValue("id")` |
| `POST /users` | 只匹配 POST | 其它方法自动 405 |
| `/files/{path...}` | 尾部通配，匹配剩余全部（含 `/`）| `r.PathValue("path")` |
| `/users/{$}` | 精确匹配 `/users/`（阻止子树匹配）| 常用于避免意外前缀匹配 |
| `example.com/` | Host 匹配 | 多域名共用端口 |

且**注册时检测冲突**（冲突直接 panic），**匹配时按"最具体者优先"**。

## 深度展开

### 1. 基础用法

```go
mux := http.NewServeMux()

mux.HandleFunc("GET /api/users/{id}", func(w http.ResponseWriter, r *http.Request) {
    id := r.PathValue("id") // 路径变量
    fmt.Fprintf(w, "user=%s\n", id)
})

mux.HandleFunc("POST /api/users", createUser)
mux.HandleFunc("GET /files/{path...}", serveFile) // 匹配 /files/a/b/c.txt
mux.HandleFunc("GET /{$}", homeHandler)           // 只匹配根路径 "/" 本身

http.ListenAndServe(":8080", mux)
```

关键点：

- **方法前缀必须大写且紧跟空格**：`"GET /x"`；
- 无方法前缀则匹配所有方法；
- **`{id}` 只匹配单个路径段**（不含 `/`）：
  `/api/users/1` ✅，`/api/users/1/posts` ❌（不匹配该 pattern）；
- **`{path...}` 是尾部通配**，只能出现在路径末尾；
- 请求其他方法命中同一路径时，**自动返回 405 并带 `Allow` 头**，不用手写。

### 2. 冲突检测与优先级

```go
mux.HandleFunc("GET /a/{x}", h1)
mux.HandleFunc("GET /a/{y}", h2) // ⚠️ panic：与上一条冲突（形参名不同但结构相同）

mux.HandleFunc("GET /a/b", h1)
mux.HandleFunc("GET /a/{id}", h2) // ✅ 合法：/a/b 更具体，优先匹配
```

优先级规则（官方定义的核心逻辑）：

1. **最具体（most specific）的 pattern 胜出**；
2. 字面量段 > 通配段：`/a/b` 比 `/a/{id}` 更具体；
3. `{$}` 比空段更具体；
4. **两个 pattern 无法比较出更具体者 → 注册时 panic**（`ServeMux` 会在 `Handle` 时检测）。

```go
// 请求 /a/b  → h1（字面量优先）
// 请求 /a/xyz → h2（通配兜底）
```

> 好处：**路由冲突在启动时暴露**，而不是线上请求进错 handler——这是标准库路由的重要工程价值。

### 3. 与第三方路由的关系

| 能力 | 标准库 1.22+ | gin / chi / echo |
|------|-------------|------------------|
| 方法 + 路径变量 | ✅ | ✅ |
| 通配符 | ✅（尾通配）| ✅（更灵活，可中间通配）|
| 正则约束 | ❌ | ✅（部分支持）|
| 路由分组 / 中间件链 | ❌ 需自己包（`http.Handler` 装饰）| ✅ 内置 |
| 参数绑定 / 校验 | ❌ | ✅ |
| 依赖体积 | 0 | 需要引入 |
| 性能 | 极快（有优化）| 相当 |

**选型建议**：

- 服务简单、想让依赖最小（网关、sidecar、内部工具）→ 用标准库；
- 需要分组、参数绑定、校验、OpenAPI 生成 → 用框架，但别把"路由能力"当唯一理由。

### 4. 中间件的正确包法

标准库没有"Use/Group"，用 `http.Handler` 装饰即可：

```go
func withAuth(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        if r.Header.Get("Authorization") == "" {
            http.Error(w, "unauthorized", http.StatusUnauthorized)
            return
        }
        next.ServeHTTP(w, r)
    })
}

mux := http.NewServeMux()
mux.Handle("GET /admin/{$}", withAuth(adminHandler))
```

注意：**`withAuth(...)` 包在注册的 handler 上，而不是整个 mux**（除非你要全局）。

### 5. 生产坑点

```go
// ❌ 坑 1：忘记尾通配语义，导致 /files 下的敏感路径也被暴露
mux.HandleFunc("GET /files/{path...}", os.ReadFile) // 需自己防目录穿越（用 os.Root）

// ❌ 坑 2：模式写错顺序导致 panic
//    "GET /a/{x}" 与 "GET /a/{x}/b" 不冲突，但 "GET /a/{x}" 与 "GET /a/{y}" 冲突

// ❌ 坑 3：把路径变量当已校验数据用
id := r.PathValue("id")  // 必须自己校验：是否为数字、是否超长、是否含特殊字符
```

- **`PathValue` 不保证格式**：`/users/../../etc/passwd` 的变量值也可能含奇怪内容，需白名单校验；
- **405 与 404 的区别**：路径存在但方法不匹配 → 405（带 `Allow`）；路径不存在 → 404；
- **Host 匹配**：`mux.HandleFunc("api.example.com/health", h)` 可做多域名分流，但 HTTPS 证书仍由 TLS 层负责。

## 高频追问

**Q：`{id}` 和 `{path...}` 能混用吗？**

不能把 `{path...}` 放在中间：`/files/{path...}/x` 是非法的（通配只能是最后一段）。
中间需要多段捕获时，只能用多个 `{a}/{b}` 或退回第三方路由。

**Q：路由匹配是前缀匹配还是精确匹配？**

1.22 之后语义更清晰：**普通 pattern 是"按段精确匹配"**，
只有以 `/` 结尾或以 `{x...}` 结尾的 pattern 才有子树/多段语义；
`{$}` 用来显式表达"就到这里为止"。

**Q：升级到 1.22 后原有代码会 break 吗？**

有一类**行为变化**：以前 `"/users/"` 匹配所有以 `/users/` 开头的路径，
某些老写法在新语义下匹配范围变化；另外 pattern 冲突现在会 panic。
升级时建议跑一遍路由注册的单元测试。

## 面试话术

> "Go 1.22 的标准库 ServeMux 已经支持 `GET /users/{id}` 这种方法和路径变量写法，
> 取参数用 `r.PathValue`，尾部多段用 `{path...}`，
> 冲突会在注册时 panic，匹配按最具体优先，方法不匹配自动 405。
> 所以'标准库路由弱'这个结论在 1.22 之后不成立了；
> 仍然用框架的理由应该是分组、参数绑定、校验这些，而不是路由本身。"
