# Go 1.24 weak 包：弱指针原理与缓存实战

> 面试频率：★★★☆☆  优先级：P1  
> 关键词：`weak.Pointer`、`weak.New`、弱引用、缓存泄漏、GC 交互、Go 1.24

---

## 面试官考察意图

考察候选人对 Go 1.24 新引入的 `weak` 包的掌握程度。
初级可能完全不知道 `weak` 包的存在，高级要能讲清楚 **weak.Pointer 与 GC 的关系、相比 sync.Pool 的优势、`weak.New` 的底层实现、以及在缓存/观察者模式中的实际应用**，并能对比 Java/Python 的弱引用机制。

---

## 核心答案（30 秒版）

Go 1.24 新增 `weak` 包，提供**弱引用**能力：

| 类型 | 作用 | 典型场景 |
|------|------|----------|
| `weak.Pointer[T]` | 包装指针，不阻止 GC 回收对象 | 缓存映射（不阻止 value 被回收） |
| `weak.New[T]()` | 创建弱持有者，关联对象生命周期 | 观察者模式、事件总线 |
| `weak.Register(e *T, f func())` | 注册清理回调，对象回收前触发 | 资源释放、链路清理 |

**核心语义：** 弱引用不增加对象引用计数，对象可被 GC 回收，回收后弱指针置 nil。

## 深度展开

### 1. 什么是弱引用？

强引用（普通指针）：
```go
a := &MyStruct{}  // 强引用，GC 不会回收 a 指向的对象
p := a            // 仍是强引用
```

弱引用（weak.Pointer）：
```go
var wp weak.Pointer[MyStruct]
wp.Store(&MyStruct{})  // 弱引用，不增加引用计数
// GC 发现对象只被弱引用 → 可以回收
// 回收后 wp.Load() == nil
```

**对比其他语言：**
- Java：`WeakReference<MyClass>`（完全相同语义）
- Python：`weakref.ref(obj)`
- Go：`weak.Pointer[T]`（Go 1.24 新增）

### 2. weak.Pointer 核心 API

```go
import "weak"

// 创建弱指针
var wp weak.Pointer[MyStruct]
wp.Store(&MyStruct{Name: "test"})

// 读取（可能为 nil）
if p := wp.Load(); p != nil {
    fmt.Println(p.Name)
}

// CAS 操作（Go 1.24+）
ok := wp.CompareAndSwap(old, new)
```

### 3. 典型场景：缓存映射（解决缓存泄漏）

**问题背景：** 用 `map[Key]*Value` 做缓存，value 指针会阻止 GC，即使内存紧张也无法回收。

**解决方案：** 用 `map[Key]weak.Pointer[Value]` 包装

```go
type Cache[K comparable, V any] struct {
    data map[K]weak.Pointer[V]
    // 辅助强引用（限制总条目数）
    // 实际生产中配合 LRU 或 TTL
}

func (c *Cache[K, V]) Set(k K, v *V) {
    if c.data == nil {
        c.data = make(map[K]weak.Pointer[V])
    }
    // 存入弱引用
    var wp weak.Pointer[V]
    wp.Store(v)
    c.data[k] = wp
}

func (c *Cache[K, V]) Get(k K) *V {
    wp, ok := c.data[k]
    if !ok {
        return nil
    }
    // Load 可能返回 nil（对象已被 GC 回收）
    return wp.Load()
}
```

**实际效果：**
```go
cache := &Cache[string, *LargeObject]{}

// 放入 100 万条数据
for i := 0; i < 1_000_000; i++ {
    cache.Set(fmt.Sprintf("key-%d", i), &LargeObject{data: make([]byte, 1024)})
}

// 触发 GC
runtime.GC()

// 即使没有手动清理，弱引用指向的对象也会被回收
// cache.Get() 返回 nil（对象已被清理）
```

### 4. weak.New：弱持有者

`weak.New` 创建一个弱持有者，当对象被 GC 回收时执行回调：

```go
type Observer struct {
    name string
}

func main() {
    obj := &MyObject{State: "active"}
    
    // 创建弱持有者：关联 obj，当 obj 被 GC 时触发回调
    w := weak.New(obj, func() {
        fmt.Println("对象即将被回收，清理资源")
        // 取消注册、关闭连接等
    })
    
    // obj 变为不可达
    obj = nil
    
    // 触发 GC
    runtime.GC()
    // 输出：对象即将被回收，清理资源
}
```

**使用场景：**
- 事件监听器自动注销
- 数据库连接断开通知
- 文件句柄关闭回调

### 5. weak.Register：清理回调

`weak.Register` 在对象回收前执行清理函数：

```go
type Channel struct {
    buf []byte
}

func NewChannel() *Channel {
    ch := &Channel{buf: make([]byte, 1024)}
    
    // 注册清理回调
    weak.Register(ch, func() {
        fmt.Println("Channel 被回收，释放资源")
        // 关闭文件描述符、取消网络连接等
    })
    
    return ch
}
```

### 6. 与 sync.Pool 的区别

| 维度 | weak.Pointer 缓存 | sync.Pool |
|------|-------------------|-----------|
| GC 行为 | 对象无强引用时回收 | GC 时**全部清空** |
| 是否有保证 | **无保证**，依赖 GC | **无保证**，依赖 GC |
| 适用场景 | 缓存映射（key→value） | 高频临时对象复用 |
| 数据恢复 | 对象被 GC 后无法恢复 | GC 后 New() 重新创建 |
| 线程安全 | `weak.Pointer` 本身安全 | sync.Pool 本身安全 |

**结论：** 
- `sync.Pool` 适合**生命周期极短的高频临时对象**（如 JSON 解析 buffer）
- `weak.Pointer` 缓存适合**有明确 key 的缓存映射**，key 存在但 value 可被回收

## 高频追问

**Q：weak.Pointer 的底层实现原理？**

Go 运行时维护一个 **weak 全局链表**，每个 `weak.Pointer` 在 Store 时加入链表。GC 时，运行时检查对象是否只被 weak 引用，若是则将其置 nil 并从链表移除。

**Q：为什么需要 weak 包？之前怎么解决缓存泄漏？**

之前依赖：
1. 手动 TTL + 定时清理（复杂，容易出错）
2. `runtime.SetFinalizer`（finalizer 在对象**确定要回收时**才调用，无法阻止回收）
3. 外部库（如 `github.com/emirpasic/gods` 的某些实现）

weak.Pointer 提供了**语言层面原生支持**，更简洁、更可控。

**Q：weak.Pointer 和 `interface{}` 的 nil 有何区别？**

```go
// weak.Pointer 的 nil：对象曾存在但已被 GC 回收
var wp weak.Pointer[MyStruct]
wp.Load() // nil（从未存储过，或已被 GC 回收）

// interface{} 的 nil：从未指向任何对象
var i interface{}
i == nil // true
```

**Q：weak 包在生产环境中的最佳实践？**

1. **不要依赖 weak.Pointer 做关键数据存储**（GC 时机不确定）
2. **配合监控**：观察 weak.Pointer.Load() 返回 nil 的频率
3. **不要在 weak 回调中分配大对象**（可能导致连锁 GC）

```go
// 生产推荐写法
type监测 struct {
    cache map[string]weak.Pointer[HeavyObject]
    mu    sync.Mutex
}

func (s *监测) Get(key string) *HeavyObject {
    s.mu.Lock()
    defer s.mu.Unlock()
    
    wp, ok := s.cache[key]
    if !ok {
        return nil
    }
    
    obj := wp.Load()
    if obj == nil {
        // 对象已被 GC 回收，清理 entry
        delete(s.cache, key)
        return nil
    }
    return obj
}
```

**Q：Java 的 WeakHashMap 和 Go 的 weak.Pointer 缓存哪个更好？**

| 维度 | Java WeakHashMap | Go weak.Pointer |
|------|-----------------|-----------------|
| GC 时机 | 参照 Java 引用队列 | Go 运行时控制 |
| 用途 | 缓存映射 | 更通用（可配合任意数据结构） |
| 性能 | 有额外引用队列开销 | 轻量级，无额外开销 |
| 适用场景 | canonical mapping（缓存键） | 任意弱引用场景 |

Go 的方案更灵活，可以自己决定数据结构；Java 的 WeakHashMap 只能做 Map。
